# VDK GID — frontend

React + TypeScript + Vite. Публичный каталог, предпочтения гостя, рекомендации,
discovery и отдельная страница места подключены к существующему FastAPI.
После первого сохранения предпочтений предлагается необязательная настройка вкуса через карточки.

## Запуск всего приложения в Docker

Из корня репозитория: `docker compose up -d --build`.
Сайт: http://127.0.0.1:8080, API/Swagger: http://127.0.0.1:8000/docs.
Отдельный Node.js на хосте не нужен. Frontend собирается в образе Node и раздаётся Nginx;
`/api/` проксируется в `api:8000`, маршруты SPA поддерживают прямое открытие.
Карта входит в сборку. `.env.local` хоста не попадает в образ; API использует `/api/v1`.
Стандартные порты: сайт — 8080, API — 8000. Внутренний proxy использует `api:8000`.
После изменения frontend требуется пересборка: `docker compose up -d --build frontend`.

## Запуск в PowerShell

Из корня VDK_GID запустите существующий backend: `docker compose up -d`.
Затем:

```powershell
cd C:\Users\vovan\PycharmProjects\VDK_GID\frontend
npm.cmd ci
npm.cmd run dev
```

Откройте http://127.0.0.1:5173. Dev proxy `/api` обращается к
`http://127.0.0.1:8000`. Параметр `VITE_API_URL` в `.env.local` позволяет
задать другой публичный URL API, включая `/api/v1`. При прямом запросе
на другой origin настройте разрешённый CORS на backend.
Не помещайте административный ключ или настройки модели в `VITE_*`.

```powershell
npm.cmd run build
npm.cmd test
```

Браузерные тесты используют Chromium (`npx playwright install chromium --no-shell`) и работающий dev server
на 5173. `frontend.spec.ts` и `taste.spec.ts` используют изолированные тестовые ответы, не добавляя
демонстрационные места в приложение или БД. `live.spec.ts` требует реальный backend
с опубликованными карточками и категорией `nature`; создаёт отдельного гостя и удаляет
его в finally. Пользовательские профили и места тест не изменяет.

## Структура

- `src/api.ts`: типы реального контракта, fetch, ошибки, сериализация фильтров.
- `src/state.tsx`: гостевая сессия, предпочтения и независимые состояния мест.
- `src/components.tsx`: карточки, графика, категории, диалоги, загрузка данных.
- `src/App.tsx`: маршруты и композиция экранов.
- `src/TasteSetup.tsx`: приглашение после опроса и экран оценки мест `/taste`.
- `src/styles.css`: токены и адаптивная дизайн-система.
- `tests/`: браузерные проверки, axe, ошибки и реальные запросы FastAPI.

Токен гостя хранится в localStorage; при запрете хранения действует до перезагрузки.
Профиль создаётся только по нажатию сохранения предпочтений. Ошибка авторизации
не создаёт нового гостя автоматически. Удаление профиля требует подтверждения.

Стоимость null отличается от 0; пояснение цены выводится вместе с суммой.
Рекомендации не передают budget_rub и используют бюджет профиля. API-клиент также
сохраняет явный null при отправке JSON. Категории каталога объединяются по ИЛИ.
Геолокация и радиус отправляются вместе, отказ не блокирует выбор без расположения.
Расположение применяется к текущей подборке, API не хранит его в профиле.
Реакции и знакомство независимы. Повторное нажатие выбранной реакции отменяет её.
Discovery: влево dislike, вправо like, вверх neutral; есть кнопки и стрелки клавиатуры.
После ошибки сохранения карточка остаётся. Пустая выдача не ослабляет фильтры.

Графические эскизы — заглушки, а не фотографии мест. При наличии photo_url
отображается фото с возвратом к эскизу при ошибке. Префикс «ДЕМО» из API сохраняется.
Нет редакторского интерфейса, погоды, маршрутов, избранного и авторизации с паролем.

## Архитектурные ограничения и цели

Локальный MVP использует SPA для небольшой React/REST интеграции. Публичные страницы
пока не рендерятся сервером: перед SEO-запуском нужны SSR/prerender, метаданные мест,
а на веб-сервере — fallback маршрутов на index.html и proxy `/api`.
`vite preview` предназначен для просмотра сборки, не production-развёртывания.

Цели для смартфона средней мощности и 4G: LCP ≤2500 мс, INP ≤200 мс,
CLS ≤0,1 на p75, JS ≤200 КБ gzip сначала и ≤80 КБ дополнительного кода маршрута,
Lighthouse accessibility ≥95 и performance ≥90. Это цели, не результаты измерений.
Все маршруты пока входят в общую небольшую сборку. WCAG AA — целевой уровень;
автоматический axe не заменяет проверку скринридером и реальными пользователями.
Проверку доступности в этой задаче выполняет Codex; постоянный владелец не назначен.

## Локальная карта места

Страница места использует `src/PlaceMap.tsx` и `public/maps/vladivostok.svg`.
Это схематическая карта береговой линии и основных дорог, без поиска и маршрутизации.
Подложка загружается с того же сайта; pan/zoom не обращаются к внешним сервисам.
При отсутствии/некорректности координат, выходе за границы и ошибке загрузки показан текст.
Кнопка «Приблизить к месту» ставит маркер в центр при масштабе 4×.
Кнопки +/− и клавиши масштаба центрируют карту на месте и меняют масштаб 1–6; перетаскивание работает мышью и касанием,
стрелки — с клавиатуры, Home/«Сбросить карту» восстанавливают вид.

Подложка: север сверху, EPSG:3857 (Web Mercator), 1600×2192,
границы в WGS84: west=131.75, south=42.95, east=132.10, north=43.30.
Долгота интерполируется линейно, широта — через Mercator; изображение и маркер
перемещаются в одном контейнере. За пределами подложки маркер не обрезается молча.

Источник — данные OpenStreetMap, полученные 2026-11-13 через Overpass API:
`https://overpass-api.de/api/interpreter`. Данные ODbL, атрибуция видима под картой:
https://www.openstreetmap.org/copyright . Тайлы OSM/2ГИС не использованы.
Снимок исходных геометрий: `scripts/map-source.json.gz` (ODbL).
Запрос: `[out:json][timeout:90];(way(42.95,131.75,43.30,132.10)["natural"="coastline"];way(42.95,131.75,43.30,132.10)["highway"~"^(primary|secondary|tertiary|trunk|motorway)$"];);out geom;`
Воспроизведение SVG из корня репозитория без сети: `python frontend/scripts/render-map.py`.
Карта не включает все улицы и подписи и не предназначена для точной навигации.

Проверка карты: `npm.cmd test -- tests/map.spec.ts` (браузер из Playwright config).
При реализации успешно выполнены production build и 7 тестов карты в Chrome
(Edge на машине отсутствовал; временная конфигурация проверки удалена).
Проверены геопривязка при pan/zoom, мышь, touch, клавиатура, мобильная ширина,
отсутствие внешних запросов, пустые/некорректные координаты, выход за границы
и ошибка загрузки изображения. Проверки использовали mock API, без изменения БД.

## Настройка вкуса

После первого сохранения опроса через 350 мс открывается приглашение с анимацией карточек.
Его можно закрыть или пропустить. Повторное редактирование предпочтений его не открывает;
кнопка «Уточнить мой вкус» в подборке позволяет вернуться к оценке позже.
Перед каждым входом в `/taste`, включая прямую ссылку и обновление страницы,
снова показывается приглашение. Карточки загружаются после «Давай попробуем»;
приглашение после первого опроса засчитывается для этого перехода без повторного окна.

Берём до 12 ещё не оценённых мест из `/discovery` с бюджетом профиля и текущим геофильтром.
12 — начальный объём короткого знакомства, а не доказанная точность персонализации.
Если подходящих мест меньше, показываем доступные; фильтры ради заполнения не ослабляем.
Вправо — like, влево — dislike. На телефонах (до 600 px) нижние кнопки скрыты:
оценка выполняется свайпом по карточке. На широких экранах доступны кнопки,
«Пока не знаю» (neutral), отмена и стрелки на сфокусированной карточке.
Раннее завершение доступно на всех экранах. Анимация приглашения зациклена;
при prefers-reduced-motion отключается.
Сохранённые оценки остаются при выходе. Незавершённая колода и история отмен в браузере
не сохраняются; при повторном входе discovery выдаёт ещё не оценённые места.

Просмотр видимой карточки (`IntersectionObserver`, не менее половины высоты), открытие
подробностей, свайпы и отмены отправляются в `/me/events`. При осознанном действии
карточка также считается просмотренной. Свайп ждёт подтверждения API перед сменой карточки.
При потерянном ответе повтор использует тот же UUID и тело; конфликт версии обновляет
состояния. Оценки применяются существующим `rules-v1`: лайки добавляют предпочтение
категориям, дизлайки исключают конкретные места. Это не дообучение Qwen.

Требуется backend с миграцией `0004_analytics`; административные ключи frontend не нужны.
Статистика доступна в существующем `/admin/analytics/summary` (см. `docs/analytics.md`).
Мобильная вёрстка поддерживает вертикальную прокрутку, анимации отключаются при
`prefers-reduced-motion: reduce`.

## Cookie и геолокация

Панель cookie предлагает сохранение расположения либо только необходимые cookie.
`vdk-cookie-choice` хранит выбор 90 дней; `vdk-location` — координаты и время
получения на один час при согласии. Браузер отдельно запрашивает геолокацию;
для неё нужен HTTPS или localhost. Без согласия координаты остаются в памяти.
«Настройки cookie» позволяет изменить выбор и удалить сохранённую геопозицию.
Cookie передаются этому сайту в HTTP-запросах; серверная схема и БД не менялись.
Гостевой токен по-прежнему хранится отдельно в localStorage.

На карте места кнопка «Моё расположение» запрашивает текущую позицию. Она отображается
синей точкой «Вы» с расстоянием до места (Haversine, по прямой, не маршрут).
«Показать обе точки» подбирает масштаб для места и пользователя. За границами подложки
позиция не проецируется на край: показано пояснение, расстояние остаётся доступным.
Координаты из cookie повторно используются до истечения часа; время получения показано.
