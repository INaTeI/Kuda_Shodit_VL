# Контракт для первого React-концепта

Backend: `http://localhost:8000`, Swagger: `http://localhost:8000/docs`.
Обычные запросы используют JSON; загрузка Excel — multipart/form-data.
В CORS разрешены `http://localhost:5173` и `http://localhost:3000`.

## Загрузка Excel редактором

1. `POST /api/v1/admin/imports/preview` — поле формы `file`, книга `.xlsx` или `.xlsm`.
2. Показать `report.errors`, предупреждения `report.places[].warnings`, число новых записей
   `report.would_create` и число существующих `report.skipped_existing`.
3. При `status: ready` предложить кнопку подтверждения. При `status: invalid` попросить исправить файл.
4. `POST /api/v1/admin/imports/{id}/apply` — без тела запроса, использовать верхнеуровневый `id` загрузки.
5. Показать `report.created` и `report.skipped_existing` из окончательного ответа.

Все три метода импорта, включая `GET /api/v1/admin/imports/{id}`, требуют `X-Admin-Key`.
Это функция редактора. Общий ключ не должен вшиваться в публичную React-сборку.
Для локального концепта его вводит редактор; перед публичным запуском нужна авторизация с ролями.
Гостевой Bearer-токен доступа к импорту не даёт.

Пример ответа по структуре (UUID и значения условные):

```json
{
  "id": "4c25cbd6-cbd5-4a68-8bdd-1a2827447daa",
  "file_name": "places.xlsx",
  "sha256": "...",
  "size_bytes": 53944,
  "status": "ready",
  "created_at": "2026-11-13T00:00:00Z",
  "expires_at": "2026-11-13T01:00:00Z",
  "applied_at": null,
  "report": {
    "file": "places.xlsx",
    "sha256": "...",
    "mode": "dry-run",
    "filled_rows": 55,
    "blank_rows": 45,
    "unique_places": 54,
    "duplicates_in_file": [],
    "errors": [],
    "created": 0,
    "would_create": 54,
    "skipped_existing": 0,
    "places": []
  }
}
```

В реальном ответе `places` содержит результат каждой уникальной карточки, `duplicates_in_file` —
обнаруженные повторы. Ошибка строки содержит номер `row` и описание `error`.
Если файл уже импортирован, `would_create` может быть 0 — это успешная проверка, не ошибка.

| Ответ | Как показать в интерфейсе |
|---|---|
| 201, ready | Предварительная проверка готова, можно подтвердить |
| 201, invalid | Показать ошибки строк, подтверждение недоступно |
| 200, applied | Импорт завершён, показать итоговые счётчики |
| 401 | Требуется правильный ключ редактора |
| 404 | ID загрузки не найден |
| 409 | Нельзя подтвердить файл с ошибками либо обнаружен конфликт данных |
| 410 | Прошёл час: загрузить книгу заново |
| 413 | Слишком большой запрос или файл |
| 422 | Неверный файл, структура, параметры запроса или UUID |

Импорт создаёт черновики. Существующие карточки пропускаются, не обновляются и не удаляются.
Повторное подтверждение того же `id` возвращает прежний результат без повторной записи.
Другой редактор может изменить БД после preview, поэтому итоговые счётчики пересчитываются при apply.
Места становятся публичными после редакторской проверки и отдельной публикации.

## Минимальный клиент на TypeScript

Готовые функции: `clients/imports.ts`. Пример использования:

```ts
const batch = await previewExcel(file, adminKey);
if (batch.status === "ready") {
  // Сначала показать отчёт и дождаться нажатия пользователем кнопки.
  const applied = await applyExcel(batch.id, adminKey);
  console.log(applied.report.created);
}
```

При передаче FormData не задавайте Content-Type самостоятельно: браузер добавит boundary.
Следует показывать состояние загрузки и отключать кнопку подтверждения на время запроса.
Повтор запроса apply безопасен после сетевого сбоя.

## Профиль и рекомендации

- Создать гостя: `POST /api/v1/profiles`, сохранить выданный `access_token`.
- Личные запросы: `Authorization: Bearer <access_token>`.
- Интересы/бюджет: `PUT /api/v1/me/preferences`.
- Подбор: `POST /api/v1/recommendations`, для первого запроса достаточно `{"limit": 5}`.
- Реакция: `PUT /api/v1/me/reactions/{place_id}`, тело `{"reaction": "like"}`.
- Места с лайком: `GET /api/v1/me/liked-places?limit=12&offset=0` возвращает страницу опубликованных мест текущего профиля.
- Другие значения: `dislike`, `neutral`. Свайп влево означает dislike, вправо — like.

Qwen подключена на сервере за тем же методом рекомендаций; адрес модели
не передаются React-клиенту. Фронт должен воспринимать `algorithm_version` как строку версии,
а не проверять только значение `rules-v1`.
`score` по-прежнему означает баллы базового алгоритма; это не вероятность и не уверенность модели.

В персональной подборке Qwen3-Embedding меняет порядок разрешённых карточек с учётом
интересов, сохранённых реакций и доступного прогноза. При ошибке или таймауте
API возвращается к `rules-v1`. Модель не создаёт новые места и не меняет ограничения.
Черновики, дизлайки и ограничения бюджета/географии фильтруются
backend до передачи кандидатов ранжировщику.

## Статистика карточек

Ответы `/recommendations` и `/discovery` дополнены `recommendation_id`.
`/me/place-states` возвращает `reaction_revision`. Для нового интерфейса свайпов
используйте `POST /api/v1/me/events`: card_view, place_open, swipe, swipe_undo.
Свайп сам меняет текущую реакцию; не дублируйте его старым PUT реакций.
UUID события сохраняется при повторной отправке; 409 требует обновления состояния.
Контракт и примеры: [analytics.md](analytics.md). TypeScript-клиент: `clients/analytics.ts`.
Группы **Статистика** и новые примеры также доступны в Swagger основного API.

### Сброс интересов

`POST /me/interests/reset` с гостевым Bearer очищает `interests` и все реакции
(like/dislike/neutral) только текущего профиля одной транзакцией.
Бюджет, токен, отметки `is_known` и историческая статистика остаются.
Ревизия каждой очищенной реакции увеличивается; повторный сброс не меняет её.
Ответ — актуальный `ProfileOut`; затем клиент обновляет `/me/place-states`.
Во frontend кнопка «Сбросить мои интересы» находится в «Предпочтениях».
