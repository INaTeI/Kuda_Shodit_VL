# Каталог Qwen в БД приложения

Источник: `recommender/data/catalog.json`, 188 мест. Это каталог для retrieval,
а не набор пользовательских оценок и не веса модели. Веб-поиск и повторная проверка
сведений при импорте не выполняются; даты проверки перенесены из исходного файла.

13.11.2026 каталог загружен в локальную БД `vdk_preview`:

- 188 новых записей: 42 опубликованы, 146 черновиков.
- В 106 записях отсутствуют координаты, в 42 — дата проверки; группы пересекаются.
- Вымышленные seed-карточки архивированы, их ID, реакции и история сохранены.
- Пользовательские профили, бюджет, интересы и статистика не удаляются.

В каталоге, рекомендациях и свайпах теперь используются 42 полные карточки.
Черновики требуют дополнения/проверки редактором, после чего их можно публиковать
обычным API. Дату импорта и координаты центра города вместо отсутствующих данных
не подставляем. Фотографии не выдумываются: frontend использует эскизы.

## Повторение импорта

С настроенными DATABASE_URL и ADMIN_API_KEY:

```sh
python -m app.importing.model_catalog --report /tmp/catalog-preview.json
python -m app.importing.model_catalog --apply --publish-complete --archive-demo --report /tmp/catalog-result.json
```

Без `--apply` запись не выполняется. Без `--publish-complete` новые записи — черновики.
Публикация выполняется только при наличии координат, источника и исходной даты проверки,
после валидации PlaceWrite. Для production требуется редакторская проверка сведений.
`--archive-demo` затрагивает только seed-ID с именем «ДЕМО:», не произвольные карточки.
Повторный импорт пропускает существующие записи, не затирая правки редактора.

Типы сопоставляются с текущими категориями по отдельным компонентам: ресторан → food,
бар → nightlife, парк → nature/relax и т. п. Исходный тип, теги и диапазоны расходов
сохраняются. Для бюджета используется верхняя граница полного диапазона; неизвестная
стоимость остаётся null.

ID PostgreSQL — стабильный UUID от исходного model_place_id. Оригинальный ID сохраняется
в source_data.model_place_id. Отчёт содержит соответствие ID модели и БД; локальная
копия — `data/imports/qwen-catalog-report.json` (исключена из Git).

События текущих карточек уже содержат place_id БД и recommendation_id. Для анализа
их можно связать с каталогом через это соответствие. Старые события демо-карточек
остаются в общей сводке; при сравнении каталогов отбирайте события по ID мест.
Основная персональная выдача по-прежнему rules-v1, отдельный сервер Qwen не изменён.
Импорт не подключает Qwen к Ranker и не дообучает модель.
