# Авторизация конструктора мест

`/constructor/` — закрытая административная страница. Публичный сайт может читать только
опубликованное оформление и фотографии. Список мест, черновые фотографии и все операции
изменения находятся под `/api/v1/editor/*` и требуют подписанную HttpOnly-сессию.

## Первый запуск

1. Создайте случайный `ADMIN_API_KEY` длиной не менее 32 символов и сохраните его только
   в серверном `.env`.
2. Сгенерируйте хеш пароля интерактивно, чтобы пароль не попал в историю команд:

   ```bash
   docker compose run --rm api python -m app.editor.hash_password
   ```

3. Запишите в серверный `.env`:

   ```dotenv
   EDITOR_USERNAME=admin
   EDITOR_PASSWORD_HASH=полученный_хеш
   EDITOR_SESSION_HOURS=12
   EDITOR_COOKIE_SECURE=true
   ```

4. `EDITOR_COOKIE_SECURE=true` используйте только после включения HTTPS. На публичном сервере
   запускать админку через HTTP нельзя: пароль и cookie смогут быть перехвачены.
5. Примените миграцию и пересоберите сервисы:

   ```bash
   docker compose run --rm migrate
   docker compose up -d --build api frontend
   ```

Смена `EDITOR_PASSWORD_HASH` или `ADMIN_API_KEY` автоматически отзывает все активные сессии.
Пустой `EDITOR_PASSWORD_HASH` полностью отключает вход.

## Модель защиты

- пароль хранится как PBKDF2-SHA256 с 600 000 итераций;
- сессия подписана HMAC, находится в HttpOnly-cookie и имеет `SameSite=Strict`;
- POST/PUT требуют заголовок `X-VDK-Editor: 1`;
- после пяти неудачных попыток с одного адреса вход временно блокируется;
- загрузка принимает только JPEG, PNG и WebP до 4 МБ;
- `expected_revision` не позволяет одной вкладке затереть изменения другой;
- cookie не содержит пароль или административный API-ключ.

Текущая версия рассчитана на один общий аккаунт редакции и один экземпляр API. Если появятся
отдельные сотрудники и разные права, следующим этапом нужны таблица пользователей, роли и
персистентный rate limit в Redis/PostgreSQL.

## Проверка

```bash
pytest -q tests/test_editor.py
node design/place-constructor/qa.mjs
```

Минимальная ручная проверка: без входа список мест возвращает `401`; вход с неверным паролем —
`401`; изменение без CSRF-заголовка — `403`; после выхода сессия снова возвращает `401`.
