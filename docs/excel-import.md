# Импорт мест из Excel

Импортёр читает лист `Места` из `.xlsx` и `.xlsm`. Макросы не выполняются, книга не сохраняется
и не изменяется. Формулы и ошибки Excel в строках данных отклоняются. Листы `Справка`,
`Категории` и `Погода` не превращаются в места.

## Повторить импорт

Команды PowerShell выполняются из корня проекта. Сначала запустите Docker Desktop.

```powershell
docker compose up -d --build
docker compose cp data/imports/places_2gis.xlsm api:/tmp/places_2gis.xlsm

# Только проверить файл и сравнить с текущей БД — без записи:
docker compose exec -T api python -m app.importing /tmp/places_2gis.xlsm --report /tmp/import-preview.json

# Записать новые места одной транзакцией:
docker compose exec -T api python -m app.importing /tmp/places_2gis.xlsm --apply --report /tmp/import-result.json
docker compose cp api:/tmp/import-result.json docs/import-result.json
```

В `.env` используется обычный DATABASE_URL приложения. Импорт работает внутри локального
контейнера; дополнительных ключей, запросов к 2ГИС и интернета для обработки файла не требуется.
Отчёт JSON содержит номера строк, действия, предупреждения, SHA-256 файла и идентификаторы.
Исходная локальная копия находится в `data/imports/places_2gis.xlsm`; она исключена из Git и
Docker-образа. После пересоздания контейнера копирование файла в /tmp нужно повторить.

## Правила загрузки

- По умолчанию — dry-run; запись только с `--apply`.
- Новые записи всегда `draft`. Отсутствующие координаты, дата проверки и ссылка остаются null.
- Опубликованная карточка должна иметь координаты, ссылку и дату проверки. Правило проверяется
  и API, и ограничением PostgreSQL. Для черновика эти поля могут быть пустыми.
- ID 2ГИС из URL — основной ключ повтора. Для остальных строк используется стабильный ключ
  по URL, либо по сочетанию названия и местоположения. Повторный запуск пропускает уже
  существующие записи и не перезаписывает изменения редактора.
- Одинаковое название само по себе не означает дубль. Короткая ссылка объединяется с прямой
  записью, только если в описании указан её ID 2ГИС и нормализованные названия совпадают.
- Строки-дубли сохраняются в `source_data.rows` основной карточки, поэтому данные не теряются.
- Несколько параллельных запусков CLI сериализуются advisory lock PostgreSQL.
- При ошибке строки файл не записывается даже частично. Ошибка БД откатывает всю транзакцию.
- Удаление строк из Excel не удаляет записи из БД. Обновление существующих мест выполняется
  редактором; автоматическое перезаписывание и синхронизация удаления не предусмотрены.

## Сопоставление полей

| Excel | БД / API |
|---|---|
| Название | name, обрезаны пробелы по краям |
| Краткое и полное описание | description; исходные значения сохранены отдельно |
| Чем интересно и необычно | activity |
| Адрес или ссылка | address; ссылка может также стать source_url |
| Широта, долгота | latitude, longitude; десятичная запятая поддерживается |
| Тип | place_type и категории по явной таблице TYPE_CATEGORIES |
| Интересы через `;` | interest_tags; отдельные теги добавляют крупные категории |
| Вход, цены входа, расходы | cost_details без потери границ диапазона |
| Цена для фильтра бюджета | price_rub — верхняя граница полного диапазона расходов на человека |
| Часы и условия посещения | opening_hours, visiting_notes |
| Источник | первая корректная HTTP(S)-ссылка, полный текст остаётся в source_data |
| Дата проверки | checked_at из файла, без подстановки даты импорта |
| Прочие колонки и примечания | source_data с исходными заголовками и значениями |

Бесплатный вход не означает нулевые общие расходы. Если диапазон расходов не заполнен полностью,
price_rub остаётся null, даже при входе 0 ₽. Например, расходы 300–500 ₽ дают price_rub=500,
а обе границы остаются в cost_details. Изображения не скачиваются; ссылка на фото, если есть,
сохраняется в исходных данных.

Крупные категории выводятся по типу и интересам. Например, сквер → nature/relax,
музей → culture, «история» добавляет culture, «необычные места» — hidden-gems.
Это техническое сопоставление, его стоит проверить редактору. Полный список —
`app/importing/excel.py`, словари TYPE_CATEGORIES и TAG_CATEGORIES.

## Просмотр и публикация

Импортированные карточки доступны через `GET /api/v1/admin/places` с X-Admin-Key.
Для просмотра всех 54 мест задайте `limit=100` (по умолчанию 20).
Ответ редактора содержит import_key и source_data. Публичный API эти исходные поля не отдаёт.
Черновики не попадают в публичный каталог и рекомендации.

После проверки карточки обновите её через `PUT /api/v1/admin/places/{id}`, заполнив обязательные
поля и передав `status: "published"`. Дату проверки проставляйте по факту редакторской проверки.
Полный диапазон цен и исходные данные при обычном редактировании карточки сохраняются.

До миграции и импорта сделан дамп `backups/before-excel-import-2026-11-13.dump`.
Ранее существовавшие карточки и профили остаются в БД. Автоматического удаления демо-мест нет.

## Проверки

```powershell
docker compose --profile test run --build --rm tests
docker compose --profile test run --rm tests ruff check --no-cache app tests
docker compose exec -T api alembic check
```

Тесты проверяют чтение и неизменность файла, заголовки в другом порядке, числа с запятой,
диапазоны цен, пустые координаты, даты, формулы, ошибки строк, идентичность объектов,
dry-run без записей, повтор без дублей, откат транзакции и запрет неполной публикации.
