# VDK GID — городской гид

Общий Swagger модели: **http://149.154.70.109/model/docs** — открыть, выбрать
POST /recommendations → Try it out → Execute. Инструкция: [docs/qwen-server.md](docs/qwen-server.md).

Сбор статистики карточек: [docs/analytics.md](docs/analytics.md). Подборки получают
`recommendation_id`; `/api/v1/me/events` принимает показы, открытия, свайпы и отмены.
Сводка редактора: `/api/v1/admin/analytics/summary`. Требуется миграция `0004`.

Отдельный сервис для проверки модели Qwen и каталога из 188 мест находится
в [recommender/README.md](recommender/README.md). Он запускается независимо на порту
8001, без PostgreSQL и без подключения к основному API.

Локальный REST API для React-приложения: каталог мест Владивостока, поиск по категориям,
бюджету и радиусу, объяснимые рекомендации и реакции гостевого профиля.
Swagger позволяет пробовать методы без фронтенда. Это MVP, публикация в интернет не выполняется.

## Быстрый запуск на Windows

Нужен запущенный Docker Desktop в режиме Linux containers. Python на хосте не требуется.
Откройте PowerShell в папке `C:\Users\vovan\PycharmProjects\VDK_GID`.

```powershell
# Только при первом запуске, если .env отсутствует:
Copy-Item .env.example .env
# Откройте .env и задайте свой длинный ADMIN_API_KEY.
docker compose up -d --build
docker compose exec api python -m app.seed
docker compose ps
```

При изменении пароля PostgreSQL в .env обновите также DATABASE_URL. Для существующего
тома изменение POSTGRES_PASSWORD само по себе пароль базы не меняет.

- Сайт: http://127.0.0.1:8080 (frontend в отдельном образе Nginx)
- Swagger: http://localhost:8000/docs
- OpenAPI JSON: http://localhost:8000/openapi.json
- ReDoc: http://localhost:8000/redoc
- Проверка готовности БД: http://localhost:8000/health/ready

Frontend входит в `docker compose up -d --build`; Node.js на хосте не требуется.
Стандартные порты: сайт — 8080, API — 8000. Proxy frontend → API работает внутри Docker.

Миграции выполняются отдельным одноразовым сервисом migrate до старта API.
Seed запускается явно и повторно не создаёт дубликаты. Он добавляет восемь категорий и
восемь ВЫМЫШЛЕННЫХ мест с префиксом «ДЕМО». Это не настоящий каталог и не проверенные цены.
Из приложенного Excel импортированы 54 черновика; подробности — docs/excel-import.md. Данные картографических сервисов через интернет не скачиваются.
Без seed таблицы пусты: для добавления только категорий используйте импорт настоящих данных
в следующей итерации либо функцию seed_categories в собственном скрипте.

## Проверка в Swagger

1. Выполните POST /api/v1/profiles без тела. Скопируйте access_token; он выдаётся один раз.
2. Нажмите Authorize. В HTTPBearer вставьте токен БЕЗ слова Bearer.
3. Выполните GET /api/v1/categories и PUT /api/v1/me/preferences:

```json
{"interests": ["nature", "culture"], "budget_rub": 1000}
```

4. Выполните POST /api/v1/recommendations с телом:

```json
{"latitude": 43.115, "longitude": 131.885, "radius_km": 10, "limit": 5}
```

5. Возьмите id из ответа и отправьте PUT /api/v1/me/reactions/{place_id}:

```json
{"reaction": "like"}
```

6. Сравните подборку после изменения предпочтений/реакций. Для отмены — DELETE реакции.
7. Для методов /admin в Authorize заполните APIKeyHeader значением ADMIN_API_KEY из .env.
   Гостевой токен не даёт прав редактора. Никогда не передавайте ключ редактора в React-сборку.

Ваша механика: влево = like, вправо = dislike, вверх = neutral. API получает значение,
а не направление; React отвечает за жест. Реакции можно создавать повторно: PUT заменяет
оценку, не добавляет дубликаты. Знакомство — отдельное поле и не стирает лайк.

## Методы

| Метод | Путь после /api/v1 | Назначение | Доступ |
|---|---|---|---|
| GET | /categories | 8 категорий | Все |
| GET | /places | Каталог с фильтрами | Все |
| GET | /places/{id} | Подробная карточка | Все |
| POST | /profiles | Новый гостевой профиль и токен | Все |
| GET | /me | Текущий профиль | Bearer |
| PUT | /me/preferences | Полная замена интересов и бюджета | Bearer |
| DELETE | /me | Удаление профиля и реакций | Bearer |
| GET | /me/place-states | Мои оценки и знакомые места | Bearer |
| PUT / DELETE | /me/reactions/{id} | Оценка / отмена | Bearer |
| PUT | /me/known-places/{id} | Знакомство с местом | Bearer |
| POST | /recommendations | Ранжированная подборка | Bearer |
| POST | /discovery | Случайные ещё не оценённые места | Bearer |
| POST | /me/events | Показ, открытие, свайп или отмена с историей | Bearer |
| GET | /admin/analytics/summary | Сводка показов и действий за период | X-Admin-Key |
| GET / POST | /admin/places | Каталог редактора / создание | X-Admin-Key |
| PUT / DELETE | /admin/places/{id} | Полная замена / архивирование | X-Admin-Key |

GET /places принимает повторяющийся `categories`, `budget_rub`, `latitude`, `longitude`,
`radius_km`, `limit`, `offset`. Категории объединяются по ИЛИ. Три географических параметра
нужно передавать вместе. Радиус — километры; координаты явно разделены на широту и долготу.
Каталог и рекомендации отдают координаты для будущего отображения меток на React-карте.
Отдельная геометрия/карта и подключение провайдера карт пока не реализованы.

## Правила рекомендаций

Сначала обязательные ограничения: публикация, категория, бюджет и точка с радиусом.
Затем исключаются знакомые и дизлайкнутые места (по умолчанию).
Баллы: 3 за каждую категорию из интересов; по 1 за лайки других опубликованных мест той
же категории (не больше 3 на категорию); ещё 2 за собственный лайк места.
Ответ содержит причины и версию rules-v1. Это объяснимый алгоритм, не ML-модель.

Отсутствующий budget_rub в запросе рекомендаций означает бюджет профиля;
явный null снимает бюджетное ограничение. Цена null означает «неизвестно» и при заданном
бюджете исключается. Цена 0 означает известные нулевые расходы указанного в price_note типа.
Отсутствие отметки «знакомо» не доказывает, что человек здесь не был.
Пустой результат имеет items: [] и total: 0; фильтры не ослабляются автоматически.

В этом MVP dislike сохраняется до замены/отмены. Он исключает конкретное место,
не категорию целиком. Neutral не меняет ранжирование, но убирает карточку из discovery.
Для нового случайного набора discovery используйте offset=0: случайная сортировка не
гарантирует отсутствие повторов между страницами; оценки исключают увиденные карточки.

Draft скрыт (404), archived исключён из подборок и возвращает 410 по прямому ID.
Удаление редактором — мягкое: ID и реакции сохраняются. PUT редактора может восстановить карточку.
Фотографии пока не загружаются: photo_url всегда null, на фронтенде нужна заглушка.
Погода, маршруты, события, отзывы, избранное, учётные записи с паролем — следующие итерации.

## Архитектура и стек

Python 3.12, FastAPI 0.115.12, Pydantic 2, SQLAlchemy 2 async, asyncpg, Alembic,
PostgreSQL 16.9. Версии библиотек закреплены; это совместимый набор, не обещание последних версий.
React — клиент будущей итерации; полноценный frontend здесь не создаётся.

```text
app/
  main.py              сборка приложения, CORS, health
  core/config.py       настройки окружения
  db/                  подключение и ORM-модели
  api/dependencies.py  авторизация и зависимости запросов
  catalog/             маршруты, схемы, запросы к БД, правила каталога
  profiles/            гостевой профиль и состояния мест
  recommendations/     отдельная логика ранжирования и случайной выдачи
  seed.py              демонстрационные записи
alembic/               версионируемые изменения БД
tests/                 интеграционные тесты на PostgreSQL
docs/                  решения по архитектуре, план развития, протокол проверок
```

Одна async SQLAlchemy-сессия на запрос. Для MVP достаточно одного приложения и БД.
Геофильтр Haversine выполняется в Python после SQL-фильтров: осознанный выбор для ~200 мест.
При существенном росте каталога перенести геозапросы в PostGIS с GiST-индексом.
Параметры SQL передаются через ORM. JSON-поля используются только для списка интересов,
сами категории и связи мест нормализованы в отдельные таблицы.

## React

CORS разрешает localhost:5173 и localhost:3000. CORS_ORIGINS в .env — JSON-массив.
Для личных запросов передавайте Authorization: Bearer <access_token>.
Токен гостя хранится клиентом; потеря токена означает потерю доступа к профилю.
Это bearer-секрет без персональных данных, срок действия в MVP не ограничен.
В базе хранится SHA-256 токена. Удаление профиля отзывает токен и удаляет реакции.

## Ежедневная работа

```powershell
docker compose up -d
docker compose logs -f api
docker compose exec api alembic current
# После изменения исходников:
docker compose up -d --build
# Остановка с сохранением каталога:
docker compose down
```

Не используйте `docker compose down -v`, если хотите сохранить базу: -v удаляет тома.
Для резервной копии без риска повреждения бинарного дампа в старом PowerShell:

```powershell
docker compose exec db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/vdk.dump'
New-Item -ItemType Directory -Force backups
docker compose cp db:/tmp/vdk.dump backups/vdk.dump
```

Восстановление выполняйте сначала в отдельной БД через pg_restore, проверив содержимое.
Для PyCharm выберите Python 3.12 и установите requirements-dev.txt в новое окружение:
имеющаяся .venv может ссылаться на отсутствующий Python. Рабочий каталог — корень проекта.
При запуске Python с хоста измените DATABASE_URL на localhost и используйте compose.local.yaml:

```powershell
docker compose -f compose.yaml -f compose.local.yaml up -d db
# В локальной .env: DATABASE_URL=postgresql+asyncpg://vdk:...@localhost:5433/vdk_gid
python -m alembic upgrade head
python -m app.seed
python -m uvicorn app.main:app --reload
```

Не меняйте DATABASE_URL в конфигурации контейнеров на localhost: там hostname БД — db.
При конфликте порта API измените API_PORT в .env.

## Перед публичным запуском

Текущий стенд привязан к 127.0.0.1; PostgreSQL не публикует порт по умолчанию.
Публичный запуск требует HTTPS/reverse proxy, нормальных учётных записей и ролей редактора,
ограничения частоты/объёма запросов и создания профилей, управления сроком токенов,
резервного копирования с проверкой восстановления, мониторинга и обновления образов.
Не используйте общий ключ редактора как постоянную систему авторизации в интернете.
Нет импорта 2ГИС, картографических API, загрузки фотографий и внешних платных сервисов.
Ничего не отправлено в GitHub; удалённый репозиторий не создан.

## Загрузка Excel через Swagger и React

В Swagger появилась группа **Импорт Excel**. Требуется X-Admin-Key (Authorize → APIKeyHeader).
Гостевой токен для этих операций не подходит.

1. POST /api/v1/admin/imports/preview: выберите файл в поле file, выполните запрос.
2. Проверьте status и report. При ready скопируйте верхнеуровневый id загрузки.
3. POST /api/v1/admin/imports/{import_id}/apply: вставьте этот id и подтвердите импорт.
4. GET /api/v1/admin/imports/{import_id}: получить сохранённый отчёт.

При invalid исправьте report.errors в книге и загрузите новый файл.
Действует ограничение 5 МБ, предварительный результат можно подтвердить в течение часа.
Повторное подтверждение безопасно. Загружаются новые черновики, существующие карточки пропускаются.
На ранее импортированном файле ожидаемо created=0 и skipped_existing=54.

Контракт для фронта и примеры: docs/frontend-api.md.
TypeScript-клиент: clients/imports.ts. Архитектура и хранение: docs/import-api-architecture.md.
Образец настоящего ответа: docs/import-api-example.json.

Проверенные исходные файлы временно хранятся в PostgreSQL, после apply их байты удаляются.
Периодически очищайте просроченные загрузки и отчёты старше 30 дней:

```powershell
docker compose exec api python -m app.importing.cleanup
```

Под будущую серверную LLM добавлен интерфейс Ranker. Текущий алгоритм остаётся rules-v1.
После выбора протокола модели адаптер подключается в get_ranker; фильтры и контракт API сохраняются.
При неверных ID, недоступности или таймауте ранжировщика применяется текущий алгоритм.
Адрес LLM и серверный токен в React передавать не требуется.
