# Независимая проверка моделей

Сервис не обращается к основному backend и PostgreSQL. Читает собственный каталог
из 188 мест в `data/`. Используется только Qwen3-Embedding-0.6B.
Основное приложение использует порт 8000, этот сервис — 8001.

## macOS / Linux

Нужен Python 3.12. Из корня репозитория:

```bash
cd recommender
python3.12 -m venv .venv
.venv/bin/python -m pip install torch==2.11.0
.venv/bin/python -m pip install -r requirements-dev.txt
bash run.sh
```

Если окружение уже установлено, из корня проекта достаточно:

```bash
bash recommender/run.sh
```

Swagger: http://127.0.0.1:8001/docs
Готовность: http://127.0.0.1:8001/health

Первый запуск рассчитывает векторы каталога. Дождитесь сообщения
`Application startup complete`. Для остановки нажмите Ctrl+C.
## Проверка через Swagger

Откройте `POST /recommendations`, нажмите Try it out и отправьте:

```json
{"query": "Хочу поиграть в боулинг", "category": "боулинг", "limit": 5}
```

Для свободного поиска:

```json
{"query": "Хочу спокойно погулять у моря", "limit": 5}
```

Бюджет задаётся полем `budget`, радиус — `latitude`, `longitude`, `radius_km`.
При строгом бюджете/радиусе места с неизвестными расходами/координатами исключаются.
`similarity` — оценка сходства, не вероятность и не оценка качества места.
Для похожих мест скопируйте `place_id` из ответа в
`POST /places/{place_id}/similar` и отправьте `{"limit": 5}`.

## Docker

Из корня проекта (основной backend запускать не нужно):

```bash
docker compose -f recommender/compose.yaml up --build -d
docker compose -f recommender/compose.yaml logs -f
docker compose -f recommender/compose.yaml down
```

Сборка требует интернета; модели при работе загружаются из локальных файлов.

## Данные и веса

Код и JSON-каталог хранятся в Git. Веса `models/qwen/`,
окружение `.venv/` и векторы `cache/` исключены из Git.
Локальный Python в `.python/` также исключён из Git; для уже подготовленного
окружения на этом компьютере повторная установка не нужна.
На этом компьютере веса скопированы из `Downloads/guide-recommender/models`.
После клонирования репозитория на другую машину скопируйте их отдельно
в `recommender/models/`, либо после установки зависимостей выполните:

```bash
cd recommender
.venv/bin/python export_models.py --download
```

Веса Qwen предобучены и не изменяются. Для эксперимента можно обучить отдельный
слой над векторами запросов; подробности ниже.
Изменения основной базы мест автоматически сюда не попадают.
`VALIDATION.md` содержит результаты проверок исходного пакета на Windows.

## Интеграционные тесты

Из папки `recommender`, после установки окружения:

```bash
HF_HUB_OFFLINE=1 DEVICE=cpu .venv/bin/python -m unittest test_api -v
```

Проверено 13 ноября 2026 на macOS, Python 3.12.16 и CPU:
Qwen — 6 тестов прошли с настоящими локальными весами.
Обе конфигурации Compose проходят `config --quiet`; сборка контейнеров не проверялась,
поскольку Docker daemon не запущен.

## Как отправить проект в Git и перенести на сервер

1. Из корня проекта проверьте изменения: `git status --short`.
2. Добавьте код и датасет:
   `git add .gitignore .dockerignore README.md recommender`.
3. Проверьте `git diff --cached --stat`: весов, `.venv`, `.python`, `cache` и `.env`
   в списке быть не должно.
4. Создайте коммит: `git commit -m "Add standalone Qwen recommender"`.
5. Отправьте текущую ветку: `git push -u origin HEAD`.
6. На сервере с Docker клонируйте репозиторий и перейдите в его корень.
7. Отдельно скопируйте локальную папку `recommender/models/qwen/` на сервер
   в такую же папку внутри клонированного проекта. Весов в Git нет.
8. Запустите `docker compose -f recommender/compose.yaml up --build -d`.
9. Дождитесь готовности по логам и проверьте
   `curl http://127.0.0.1:8001/health` на сервере.

Для проверки Swagger со своего компьютера используйте SSH-туннель:
`ssh -L 8002:127.0.0.1:8001 USER@SERVER`.
Пока SSH работает, откройте http://127.0.0.1:8002/docs на своём компьютере.
Замените USER и SERVER на данные своего сервера. Порт 8002 выбран, чтобы
туннель не конфликтовал с локальным сервисом на 8001.

Это отдельный сервис: основной backend и PostgreSQL для этих шагов не нужны.

## Экспериментальное обучение поиска

`train_adapter.py` обучает небольшую остаточную линейную проекцию запросов поверх
замороженной Qwen. Это обучение дополнительного слоя, а не дообучение 0.6B весов
трансформера. Оно не требует GPU, не изменяет основной backend и исходную модель.

Из папки `recommender`:

```bash
HF_HUB_OFFLINE=1 DEVICE=cpu .venv/bin/python train_adapter.py --report data/adapter_report_v2.json
```

Данные: `data/retrieval_examples.json`, 64 синтетических обучающих запроса,
16 для выбора параметров и 16 отдельных тестовых запросов. Подходящие места
определяются по типам и тегам каталога. Это слабая разметка, не реальные оценки
пользователей. Тест проверяет новые формулировки на том же каталоге, не новые места.
Параметры выбираются только по validation; тест не используется при обучении.

Отчёт: `data/adapter_report.json`. На этом небольшом наборе NDCG@5 вырос
с 0.6373 до 0.8949 (шкала 0–1, учитывает попадание релевантных мест в начало выдачи).
Это не процент правильных ответов и не гарантия улучшения любого пользовательского запроса.
Исходный Qwen остаётся доступен для сравнения.

По умолчанию сервис использует базовый Qwen. Старый `models/query_adapter.npz`
оставлен для истории и отвергается новым загрузчиком: у него нет результата проверки.

Новые кандидаты сохраняются в уникальные `models/adapters/<version>.npz`, а отчёт —
в `data/adapter_report_v2.json`. Файлы моделей исключены из Git. Существующий файл
никогда не перезаписывается, в том числе при явном `--output`.

Кандидат допускается только при улучшении validation, отсутствии ухудшения test
и отсутствии ухудшения каждого случая из `data/retrieval_regressions.json`.
Это известные ошибки из аудита, а не независимый тест новых намерений.
Если допуск не пройден, команда возвращает код 2; NPZ имеет `approved: false`
и не может загружаться сервисом. Старый отчёт `adapter_report.json` — история,
его нельзя считать результатом последней проверки.

Только для прошедшего проверку кандидата можно явно включить эксперимент:

```bash
QUERY_ADAPTER_MODE=experimental QUERY_ADAPTER_PATH=models/adapters/<version>.npz bash recommender/run.sh
```

Один `QUERY_ADAPTER_PATH` больше не включает адаптер. `/health` показывает
`adapter_mode` и `query_adapter_enabled`. Обычный `bash recommender/run.sh`
использует исходный Qwen. Эксперимент не является автоматически утверждённой заменой.

Идентификатор совместимости строится по содержимому файлов весов и каталога,
текстам, инструкции запросов, длине последовательности и точности чисел.
Копирование без изменения содержимого и смена mtime больше не ломают совместимость.
При реальном изменении конфигурации или содержимого нужен новый адаптер.

Запросы о прогулке теперь отдельно ограничиваются парками, скверами, набережными
и другими предусмотренными типами мест на открытом воздухе. Это правило фильтрации,
которое работает и без обученного слоя. Если одновременно упомянуто несколько типов
отдыха, сервис не угадывает выбор за пользователя.

Поиск `POST /places/{place_id}/similar` использует исходные векторы мест Qwen;
слой запросов к нему не применяется. Передайте ID выбранного места и `{"limit": 5}`.
С `{"same_type": false}` поиск выполняется среди разных типов мест.

Проверки с включённым адаптером (из папки `recommender`):

```bash
HF_HUB_OFFLINE=1 DEVICE=cpu .venv/bin/python -m unittest test_api test_query_adapter test_model_identity -v
```

## Исправления после ML-аудита

- Основной режим — базовый Qwen; универсальная проекция больше не включается автоматически.
- Для явного запроса SUP и бассейна действует строгий отбор по подтверждённым типам/тегам.
- Точное полное название карточки имеет приоритет среди разрешённых мест. Оно не
  трактуется как текстовая категория; бюджет, география и исключённые ID сохраняются.
- Одна явная сумма «до 500 рублей», «до 1 500 ₽» в query распознаётся как бюджет,
  если поле budget не передано. Явное значение поля, включая null, имеет приоритет.
  Несколько разных сумм и неопределённое «недорого» не интерпретируются автоматически.
  В ответе filters.budget_source показывает request, query или null.
- Для неизвестных сложных намерений сервис по-прежнему выполняет смысловой поиск;
  надёжный универсальный отказ и понимание произвольных условий пока не реализованы.
- Неизвестные координаты и цены не заполняются предположениями.
